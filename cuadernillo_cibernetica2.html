Unidad 1

Fundamentos de programación orientada a objetos con Java

Aprendizajes 1 a 8

1.1 Conceptos básicos de la POO

La programación orientada a objetos organiza un programa en objetos que tienen datos (atributos) y comportamiento (métodos), en lugar de solo una secuencia de instrucciones.

Clase: plantilla que define atributos y métodos. Objeto: instancia concreta de una clase; tiene identidad (es distinto de otros objetos aunque tenga los mismos valores), atributos (estado) y métodos (comportamiento). Paquete: agrupa clases relacionadas (java.util, javax.swing).
Pilares:
• Abstracción: modelar solo lo esencial.
• Encapsulamiento: ocultar los datos (private) y exponer métodos.
• Herencia: crear clases a partir de otras.
• Polimorfismo: un mismo mensaje, distintos comportamientos.

Organización de un programa en Java: el código se escribe en clases (una clase pública por archivo .java, con el mismo nombre), dentro de paquetes; la ejecución inicia en el método public static void main(String[] args).

1.2 UML: diagramas de clase y de objetos

El Lenguaje Unificado de Modelado (UML) es un estándar gráfico para diseñar software. El diagrama de clase tiene tres compartimentos: nombre, atributos (visibilidad nombre : tipo) y métodos (visibilidad nombre(parámetros) : tipoRetorno). El diagrama de objetos muestra instancias: nombreObjeto : Clase (subrayado) y los valores de sus atributos.

1.3 Del diagrama de clase al código: constructor, getters y setters

public class Rectangulo {
    private double base;      // atributos privados
    private double altura;

    public Rectangulo(double base, double altura) { // constructor
        this.base = base;
        this.altura = altura;
    }
    public double getBase() {          // getter: consulta
        return base;
    }
    public void setBase(double base) { // setter: modifica
        this.base = base;
    }
    public double area() {             // comportamiento
        return base * altura;
    }
}
  • Constructor: método especial con el mismo nombre de la clase y sin tipo de retorno; se ejecuta con new e inicializa los atributos.
  • Getter (getX()): devuelve el valor de un atributo privado.
  • Setter (setX(valor)): cambia el valor; puede validar antes de asignar.
  • this: el objeto actual; this.base = base asigna el parámetro al atributo con el mismo nombre.
  • Los atributos son private y los métodos public: así se aplica el encapsulamiento.

1.4 Arquitectura modelo-vista-controlador (MVC)

Separa el programa en tres responsabilidades: el modelo (clases con los datos y la lógica), la vista (lo que ve y usa el usuario: consola o formulario) y el controlador (recibe las acciones de la vista, crea los objetos del modelo y les envía mensajes). En el controlador se instancia la clase con new y se llaman sus métodos con notación punto: objeto.metodo().

🔁 Flujo de mensajes en MVC

1.5 Métodos de clase y de instancia

Método de instancia: trabaja con los atributos de un objeto; se llama sobre el objeto: r.area().
Método de clase (static): pertenece a la clase y no necesita un objeto: Math.sqrt(16), Integer.parseInt("12").

Componentes de un método: public double calcularIva(double precio) { return precio * 0.16; } → modificador de acceso (public), tipo de retorno (double, o void si no devuelve nada), identificador (calcularIva), parámetros (double precio) y bloque de sentencias entre llaves.

2.2 Excepciones: try y catch

Una excepción es un evento que ocurre durante la ejecución e interrumpe el flujo normal del programa (dividir entre cero, acceder a un índice que no existe, convertir un texto inválido). Con try/catch se atrapa y se maneja, en lugar de que el programa termine con error.

try {
    int n = Integer.parseInt(texto);   // código que puede fallar
} catch (NumberFormatException e) {     // tipo de excepción que se maneja
    System.out.println("Escribe un número entero");
}

Excepciones comunes: ArithmeticException (división entera entre 0), ArrayIndexOutOfBoundsException, NumberFormatException, InputMismatchException (Scanner recibe un dato del tipo incorrecto), NullPointerException.

2.4 Estructuras de datos y arreglos unidimensionales

Una estructura de datos organiza varios datos para usarlos de forma eficiente. Es estática si su tamaño se fija al crearla (arreglos) y dinámica si puede crecer o disminuir durante la ejecución (ArrayList).

Un arreglo guarda un número fijo de elementos del mismo tipo, accesibles por un índice que va de 0 a length - 1.
int[] v = new int[5]; (todos en 0) · double[] notas = {8.5, 9, 7}; · String[] nombres = new String[30];

3.1 Herencia: superclase y subclase

   
La herencia permite crear una clase (subclase o clase hija) a partir de otra (superclase o clase padre) con extends. La subclase recibe los atributos y métodos no privados de la superclase y puede agregar nuevos o especializar los existentes: así se reutiliza código. En Java una clase solo puede extender a una clase, y todas heredan, directa o indirectamente, de Object.

   

    
class Persona {
    protected String nombre;
    public Persona(String nombre) {
        this.nombre = nombre;          // this: el objeto actual
    }
    public String saludar() {
        return "Hola, soy " + nombre;
    }
}

    
class Estudiante extends Persona {
    private String cuenta;             // atributo agregado
    public Estudiante(String nombre, String cuenta) {
        super(nombre);                 // constructor de Persona
        this.cuenta = cuenta;
    }
    @Override
    public String saludar() {          // especialización
        return super.saludar() + ", mi cuenta es " + cuenta;
    }
}

   

   
super se refiere a la superclase (su constructor o sus métodos); this, al objeto actual. Una relación de herencia se lee «es un»: un Estudiante es una Persona.

  


  

   
3.2 Colaboración de clases

   
Las clases colaboran cuando un objeto usa a otro para cumplir su tarea: tiene un atributo de otra clase o le envía mensajes. Se lee «tiene un»: un Grupo tiene una lista de Estudiante; un Controlador crea y usa un objeto del Modelo; una Ventana tiene botones y campos de texto.

   
class Grupo {
    private ArrayList<Estudiante> alumnos = new ArrayList<>();
    public void inscribir(Estudiante e) { alumnos.add(e); }   // colaboración
    public int total() { return alumnos.size(); }
}

  


  

   
3.3 Polimorfismo, clases abstractas e interfaces

   
El polimorfismo permite tratar objetos de distintas subclases como si fueran de la superclase; al llamar un método, Java ejecuta la versión de la clase real del objeto (enlace dinámico). Así un ciclo puede procesar figuras, animales o empleados de distintos tipos con el mismo código: es un mecanismo de especialización y automatización.

   
    
    
  • Sobreescritura (override): la subclase redefine un método con la misma firma (nombre y parámetros) que el de la superclase; se marca con @Override.
    • 
    
  • Sobrecarga (overload): varios métodos con el mismo nombre y distintos parámetros, en la misma clase.
    • 
    
  • Clase abstracta (abstract class): no se puede instanciar; puede tener métodos abstractos (sin cuerpo) que las subclases deben implementar.
    • 
    
  • Interfaz (interface): declara métodos que una clase se compromete a implementar con implements; una clase puede implementar varias interfaces.
    • 
   

   

    
🔷 Polimorfismo en un arreglo Figura[]

    

    
    

    

   

   
abstract class Figura {
    public abstract double area();          // sin cuerpo
}
class Circulo extends Figura {
    private double r;
    public Circulo(double r) { this.r = r; }
    @Override
    public double area() { return Math.PI * r * r; }
}

4.1 Interfaz de consola vs. interfaz gráfica

   

    
Consola: el programa controla el orden; pregunta y espera (Scanner). La interacción es secuencial.

    
Formulario (GUI): el usuario decide qué hacer y cuándo; el programa responde a eventos (clics, teclas) mediante listeners. La interacción es dirigida por eventos.

   

   
En ambos casos conviene separar la presentación (vista) de la lógica (modelo): la misma clase Rectangulo puede usarse desde la consola o desde un formulario. Un diagrama de secuencia muestra, en el tiempo, los mensajes entre el usuario, el programa principal y las clases de lógica.

   
Sistema de coordenadas: el origen (0, 0) está en la esquina superior izquierda; x crece a la derecha y y crece hacia abajo, en píxeles. Con setLayout(null) se coloca cada componente con setBounds(x, y, ancho, alto).

   

  


  

   
4.2 Jerarquía de clases de AWT/Swing

   
Swing (paquete javax.swing) se construye sobre AWT (java.awt) usando herencia. Por eso todos los componentes comparten métodos como setBounds, setVisible o setEnabled, heredados de Component, y los contenedores pueden agregar componentes con add, heredado de Container.

import javax.swing.*;
import java.awt.event.*;
public class Ventana extends JFrame implements ActionListener {
    private JTextField campo = new JTextField();
    private JButton boton = new JButton("Aceptar");
    private JLabel salida = new JLabel();
    public Ventana() {
        setTitle("Ejemplo");
        setSize(400, 200);
        setLayout(null);
        campo.setBounds(20, 20, 200, 25);
        boton.setBounds(230, 20, 100, 25);
        salida.setBounds(20, 60, 300, 25);
        add(campo); add(boton); add(salida);
        boton.addActionListener(this);
        setDefaultCloseOperation(JFrame.EXIT_ON_CLOSE);
        setVisible(true);
    }
    @Override
    public void actionPerformed(ActionEvent e) {
        salida.setText("Hola, " + campo.getText());
    }
    public static void main(String[] args) { new Ventana(); }
}
